# MAPS.md — eval-map inventory & provenance

Central replacement for the retired per-map `*.umap.NOTE.md` siblings (deleted
2026-07-16; they were human-only docs no code ever read — and two of them leaked
agent-undisclosed tuning values into the substrate, which workspace-backend
agents can read). This file lives under `docs/` **deliberately**: agent-visible
surfaces are composed from the substrate project trees (`UE-projects/<substrate>/`)
only, so nothing in `docs/` can ever reach a model under test.

## Conventions

**Four maps went FLAT on 2026-08-20, deliberately.** `L_MudLane`, `L_TintTrack`,
`L_RaceArena` and `L_OldDoorYard` moved out of their per-task folders to
`Content/Maps/<name>.umap` because each is now SHARED by a `-cpp`/`-bp` surface pair.
`task_layout.stage_per_task_dirs_active_only` deletes every per-task directory whose name
is not the active task id, so a foldered map named after one leg vanishes from the other
leg's workspace; a flat map is a FILE at the Content/Maps root, which that stager cannot
see, so it survives for both. This is the layout the only working pair
(`gp-glide-stamina`, `L_GlideStamina`) has always used. Note the side effect: the L2
automation filter prefix is derived from the map's folder, so these four moved from
`Project.Functional Tests.Maps.<task-id>.<Map>.<Class>` to
`Project.Functional Tests.Maps.<Map>.<Class>`.

- The committed `.umap` binary is the **only** map source: the runner loads it
  directly, never re-bakes, and a missing binary is an explicit **L2 FAIL**
  (`cb lint` also errors statically on a fixture map with no committed binary).
  The text scaffolders (`Tools/scaffold_L_*.py` + the runner's
  `scaffold_map.py`) were retired 2026-07.
- Any authoring route is fine — hand-authoring in the editor, aura-mcp — as long
  as the resulting binary is committed. Authoring needs a real RHI
  (**no `-nullrhi`**); L2 test runs keep `-nullrhi`.
- New tasks put maps in per-task folders: `Content/Maps/<task-id>/L_<Map>.umap`.
  Foldered maps gain a segment in the automation name:
  `Project.Functional Tests.Maps.<task-id>.<Map>.<Class>` (runner derives this).
  The flat root-level maps predate the convention (migration pending). They are
  no longer an isolation leak: `task_layout.stage_root_maps_active_only` deletes
  every root-level `*.umap`/`*.uasset` (and legacy `*.umap.NOTE.md`) whose stem
  is neither named by the ACTIVE task spec nor in `ROOT_MAPS_SHARED_KEEP`, and
  BOTH agent surfaces call it — `graded_scratch.compose` on every compose that
  has a spec, and `workspace.build_workspace` for the workspace backends. What
  the migration still buys is layout consistency, not leak closure.
- Maps are minimal measurement chambers: the placed scaffold actor (when the task
  has one) + the placed `AFunctionalTest` fixture, nothing else unless listed.

Per-fixture dependencies worth knowing (formerly buried in NOTEs): the GAS pawn
tasks (`gp-glide-stamina-cpp`, `gp-poison-dot-stack-cpp` — and, historically, the
retired `gp-gas-launch`) rely on the ability-aware pawn resolver in
`Source/CraftBenchTests/CraftBenchPawnFunctionalTest.cpp`, which picks the agent's
`ACraftBenchCharacter` subclass by granted ability tag so multiple committed pawn
subclasses can coexist.

`DefaultEngine.ini` deliberately keeps `GameDefaultMap`/`EditorStartupMap` on a
neutral ENGINE map — a live editor never locks a task map; the verifier passes
maps explicitly on the automation command line. The committed values differ per
substrate and both are fine: `CraftBenchTemplate` uses
`/Engine/Maps/Templates/Template_Default.Template_Default`, `ThirdPerson` uses
`/Engine/Maps/Entry.Entry`. The rule the `startup-maps` envgate probe actually
enforces is the invariant, not the literal value — it FAILs only when a
`Default*Map` points INTO `Content/Maps`.
